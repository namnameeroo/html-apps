1개요 & 문제 정의

전업·준프로 신발 리셀러는 매입 수익을 위해 여러 2차 시장 경매와 매물을 24시간 모니터링하며 입찰한다. 동시에 뜨는 경매를 사람이 건별로 판단·입찰·결제하는 건 노동 집약적이고, 놓친 매물은 곧 기회비용이다.

제품 정의. "매물을 추천해주는 툴"이 아니라, 리셀러가 예산·조건만 걸면 2차 시장 경매에서 시세를 판단해 자율로 입찰·낙찰하고, 낙찰 즉시 온체인으로 정산까지 실행하는 소싱 에이전트다. 사람은 예산 한도와 조건만 한 번 승인하고, 이후 탐색·가치평가·입찰·낙찰·정산은 에이전트가 사람 승인 없이 한도 내에서 실행한다.

왜 이 도메인인가. ① 실시간 경매는 사람이 건별 승인 물리적으로 불가 → 자율 결제의 자명한 명분. ② 신발은 시세 comps가 명확(체결 이력·모델·사이즈)해서 AI의 "공정가 판단"이 검증가능. ③ 소액~중액 다건이라 데모 중 트랜잭션이 다수 발생.
범위 못박기. "나이키 SNKRS 드랍 스나이핑"이 아니다. 그건 결제가 리테일 체크아웃이라 낙찰+USDC 정산 구조가 깨진다. 반드시 2차 시장 경매/매물 소싱으로 좁혀야 결제 인프라가 네이티브하게 붙는다.

시장 구조 · 리셀러는 왜 서로 거래하나

근본 수요는 의도된 희소성이다. 브랜드(조던·아디다스·뉴발란스 협업 등)는 하이프 모델을 일부러 적게 생산한다. 수요는 많은데 발매 물량이 적어 정가에서 시장이 청산되지 않고, 이 정가와 시장가의 갭이 리셀 프리미엄이 된다. 발매(1차 시장) 물량은 추첨·봇·대기열로 접근 자체가 제약되므로, 한 켤레를 확보하는 것 자체가 가치다.

리셀러는 소비자뿐 아니라 서로(2차 시장)도 거래하는데, 이유는 다음과 같다:

  • 차익거래. 같은 신발이 플랫폼·지역·사이즈마다 가격이 달라, 저평가 매물을 사서 비싼 곳에 되판다.
  • 사이즈·재고 리밸런싱. 안 팔리는 사이즈를 그 수요가 있는 다른 리셀러에게 넘겨 현금화한다.
  • 볼륨 소싱. 전업 리셀러는 발매만으로 물량이 안 되므로, 다른 리셀러·딜러·창고정리에서 대량 매입해 재고를 채운다.
  • 투기·타이밍. 발매 직후 가격이 꺼졌다가 오르는 모델을 쌀 때 사서 보유 후 판다 — 신발을 자산처럼 운용.
  • 유동성. 작은 마진에 빨리 털어 자본을 회전시키려는 리셀러의 매물을, 여유 자본 있는 리셀러가 받는다.

결국 리셀러의 수익 원천은 정보(진짜 시장가를 앎)·접근(희소 물량 확보)·자본(볼륨 매입·보유)·속도(저평가 매물 선점)·신뢰(정품 검수 프리미엄) 중 남보다 나은 우위에서 나온다.

제품의 수익 논리

StockX·GOAT·크림 등이 체결 시세(comps)를 공개하므로 "공정가"가 계산 가능하다. 따라서 본 에이전트의 돈 버는 논리는 명확하다:

comps로 공정가를 판단 → 그보다 싸게 올라온 매물을 자율 입찰로 선점 → 시장가에 재판매해 마진. 즉 제품은 리셀러 수익 원천 중 정보(공정가 판단)와 속도(24시간 선점)를 자동화한다. "여러 경매를 사람이 못 지켜봐 놓치는 저평가 매물"이 곧 타겟 수요다.

2타겟 & 페르소나

1차 타겟: 2차 시장에서 볼륨으로 소싱하는 준프로·전업 리셀러. 이들은 예산=운영자본 개념이 명확하고, 시세 판단이 본업 스킬이라 AI가 대체할 가치가 크며, 다건 소싱이라 자율화 효과가 즉시 체감된다.

확장 TAM

사이드허슬 플리퍼(대중, 소액 다건), 신발=자산 투자자(운영 없이 ROI 추구). 데모에는 관념적이라 확장 서사로만 사용.

데모 페르소나 · 전업 리셀러 "지훈"

Jordan 1 / 270 / 개당 20만원↓ / 기대 마진 30%↑ / 총예산 500만원 / 24h. 조건을 걸고 자면 에이전트가 밤새 경매를 돌며 자율 소싱.

지훈이 거는 조건은 곧 Intent Mandate(§7)이며, 이것이 사람의 유일한 개입 지점이다.

3대회 적합성 · 심사기준 매핑

미션 "AI Agent가 매 단계 사람 승인 없이, 정해진 한도 내에서 스스로 결제를 처리"를 "사람은 예산·조건만 승인, 나머지 자율 집행" 구조가 그대로 구현한다. 실시간 경매 특성상 자율성 정당화가 자명하고, 다건 소싱이라 라이브 실증(기준 3)에 유리하다.

4시스템 아키텍처

사람은 최상단에서 예산·조건만 승인하고 손을 뗀다. 소싱 에이전트의 4개 하위 에이전트가 승인 없이 자율 실행되며, 셀러 목(mock) 에이전트와 A2A 입찰로 낙찰하고 Solana devnet에서 정산한다.

세 축 요약. ① 세로(사람→자율): 사람은 예산·조건만 승인, 이하 전체가 승인 없이 자율 — 미션 문구를 시각화. ② 가로 파이프라인: 예산·정책 → 가치평가(Gemini) → 자율입찰·낙찰(그리디) → 에스크로·정산(Solana). ③ A2A 입찰 루프: 낙찰 에이전트가 셀러 목 에이전트와 bid/accept/counter를 주고받아 "추천 챗봇"과 갈리는 차별점을 만든다.

6A2A 전략

"A2A"는 두 층위로 쓰인다. 둘을 분리해야 리소스 배분이 정확해진다. 특히 소싱 경매는 입찰 경쟁이 도메인의 네이티브 기제라 A2A가 억지 없이 붙는다(인플루언서 도메인 대비 강점).

경쟁형 A2A (제품 기제)

낙찰 에이전트 ↔ 셀러 목 에이전트가 입찰/재입찰을 주고받는 경매. 목적은 "단방향 선택 = 스마트 쇼핑카트" 비판(기준 4)을 피하는 것. 풀 흥정이 아니라 구조화된 입찰 라운드로 최소 구현.

위임형 A2A (인프라, 이미 구현)

hop-budget 엔벨로프 + 게이트웨이 권위 hop 카운터 + sender-binding 강제. 다중 홉으로 지출 권한이 위임되며 각 단계에서 한도 초과가 차단됨.

도메인 매핑. 위임형 A2A를 소싱 공급망에 붙이면: 리셀러 에이전트 → (소싱 대행/딜러 에이전트) → 개별 셀러 에이전트로 예산 권한이 홉을 타고 내려가고, hop-budget이 각 단계에서 초과 지출을 강제 차단한다. sender-binding 403·hop 초과 400이 데모에서 "권한 위임이 실제로 강제됨"을 보여준다.

결론: 경쟁형 A2A는 입찰이 네이티브라 최소 비용으로 성립. 리소스는 코어 JSON-RPC 스펙 완성도보다 위임형 A2A의 도메인 매핑에 투자한다.

7프로토콜 구현 상태 & 방향

기준 2번은 "차세대 결제 프로토콜(AP2, A2A, x402 등) 연동 구조"로, 예시 나열이지 전부 요구하는 체크리스트가 아니다. 하나를 강하게 실증하면 프로토콜 축은 충족된다.

프로토콜상태내용 · 방향
x402충족 (강)실 402 왕복 — 판매자가 X-Payment 없으면 402 챌린지 반환, 구매자가 amount·expiry 대조 검증 후 서명. 방향: nonce/expiry 강제(replay 거부)로 신뢰도 마감.
A2A부분 (중)hop-budget 엔벨로프 + 권위 hop 카운터 + sender-binding + 서명된 Agent Card 디스커버리 실재. 방향: 코어 JSON-RPC 확장 대신 §6 도메인 매핑에 투자.
AP2실구현 예정현재 Mandate가 서명 없는 객체 → 최대 리스크. 방향: 아래 2단 권한 체인으로 실구현.

AP2 실구현 방향 (개념)

적대적 심사의 "그냥 dict" 지적을 무력화하는 건 AP2가 보장하려는 보안 속성 — 검증가능·부인방지·제약구속 권한위임을 실제로 강제하는 것이다. 완전한 W3C VC/DID 스펙을 쫓지 않고, 이미 있는 Ed25519 JWS를 재사용해 2단 체인을 만든다.

Intent Mandate — 사람이 서명

"모델 M, 사이즈 S, 개당 최대가 P, 마진 R%↑, 총 예산 X, 마감 T까지." 사람이 한 번 서명하는 권한의 뿌리. 그림 1의 "사람 · 유일한 개입 지점"을 암호학적으로 실체화한다.

Cart(낙찰) Mandate — 에이전트가 서명

낙찰 확정 내역 "매물 ID·낙찰가·합계 Y ≤ X". Intent Mandate 해시를 임베드해 권한 출처를 증명(부인방지).

검증-전-지출(verify-before-spend). 지출 시점(policy.permits())에서 ① Intent 서명 검증 ② 낙찰이 Intent에서 파생됐는지(해시 바인딩) ③ 낙찰가·모델·마감이 Intent 제약 안인지 확인하고, 하나라도 실패하면 결제를 거부한다. 서사는 "사람의 단 한 번 서명된 승인 → N건의 자율 결제, 각 건이 그 승인에 대해 검증".

수용 기준(데모 킬러샷). Mandate를 예산 초과로 변조하면 결제가 실제로 거부되는 장면. "서명이 진짜 검증되고, 실패 시 실제로 막힌다"가 적대적 심사를 무력화하는 유일한 증거다.

8데모 유저 시나리오

데모는 라이브 트랜잭션이 실제로 터지는 것(기준 3)을 중심에 둔다. 큰 딜 1건보다 다건 소싱이 화면에서 강렬하다.

  1. 위임(사람의 유일한 개입). 지훈이 "Jordan 1 / 270 / 개당 20만원↓ / 마진 30%↑ / 총예산 500만원 / 24h" 입력 → [에이전트에게 위임] → Intent Mandate 서명 생성.
  2. 가치평가. 에이전트가 매물 스캔 → Gemini가 comps로 공정가·최대입찰가 산정(화면에 "공정가 24만 · 최대입찰 21만" 근거 표시).
  3. 자율입찰(A2A). 셀러 목 에이전트들에 입찰 발송 → accept/counter/reject 수신 → 예산 내 다건 낙찰. 화면에 입찰 로그 흐름.
  4. 정산. 낙찰 즉시 각 건 USDC 에스크로 예치 → (MVP)검수 플래그 → 자동 릴리스. devnet에 txn 다수 발생, explorer 링크로 실증.
  5. 킬러샷. 예산 초과 입찰을 일부러 시도 → permits()가 Mandate 검증 실패로 결제 거부하는 장면 시연.
